# SeaTunnel 2.3.8 内存问题修复 — 内网部署变更指南

> **基线版本**: SeaTunnel 2.3.8 (hzbank-seatunnel 分支)
> **变更类型**: JAR 包替换 + 配置文件修改，需停服重启
> **适用环境**: Zeta CLUSTER 模式 (Master + Worker 集群)

---

## 变更摘要

两次生产堆 Dump 分析（`dump_log` Master OOM + `dump_log2` Worker 内存膨胀）定位以下根因，本次变更共涉及 **3 个 JAR 包替换** + **4 个配置文件修改**：

| 根因（Dump 暴露的生产环境实际值） | 修复方式 |
|:---|:---|
| `hazelcast.operation.generic.thread.count = 50` → RingBuffer 积压 OOM | 🔴 配置修改 |
| Checkpoint 状态更新同步阻塞 60 秒 + 重复序列化 | 🔴 JAR (starter) |
| Checkpoint 大对象 >2MB 直接进老年代 Humongous | 🔴 JAR (starter) |
| finishedJobState 等 IMap 无 TTL / TTL=24h 常驻 | 🔴 配置修改 + JAR (starter) |
| Doris HTTP 26 个独立连接池 → 129 DirectArena / 45MB | 🔴 JAR (connector-doris) |
| stream-load-check 12 个独立线程池 → DelayedWorkQueue 堆积 | 🔴 JAR (connector-doris) |
| JDBC 连接未关闭 → 2 个 abandoned-connection 线程 | 🟡 JAR (connector-jdbc) |

> **说明**：引擎侧修复（CODE-1/2/3 + ConfigShadeUtils）全部编译打包在 `starter/seatunnel-starter.jar`（fat JAR，39MB）这一个文件中。生产环境通过启动脚本 `CLASS_PATH=lib/*:starter/seatunnel-starter.jar` 加载，`lib/` 只放第三方依赖，引擎代码都在 fat JAR 内。

## 一、更新步骤

### 1.1 发布包获取

| 文件 | 大小 | 说明 |
|------|:--:|------|
| `seatunnel-jars-only.tar.gz` | 46MB | 仅 3 个变更 JAR，用于已有安装包的增量更新 |
| `seatunnel-home-full.tar.gz` | 1.7GB | 完整 SeaTunnel 发布包 |

**增量包解压后**：

```
jars/
├── starter/
│   └── seatunnel-starter.jar          39M  ← 引擎全部修复 (CODE-1/2/3)
└── connectors/
    ├── connector-doris-2.3.8.jar      12M  ← NEW-1/2/3
    └── connector-jdbc-2.3.8.jar      1.1M  ← NEW-4/5
```

> 以下步骤以 **增量 JAR 包** 为例。使用全量包直接解压到 `$SEATUNNEL_HOME` 替换即可，但 config 目录需手工合并（见 1.4 节）。

### 1.2 停服

```bash
# 在所有节点执行，先停 Worker，再停 Master
$SEATUNNEL_HOME/bin/stop-seatunnel-cluster.sh

# 确认全部进程退出
jps | grep -i seatunnel
# 应无输出
```

### 1.3 部署 JAR 包

```bash
cd $SEATUNNEL_HOME

# ---- 备份旧 JAR ----
cp starter/seatunnel-starter.jar          starter/seatunnel-starter.jar.bak.$(date +%Y%m%d)
cp connectors/connector-doris-2.3.8.jar    connectors/connector-doris-2.3.8.jar.bak.$(date +%Y%m%d)
cp connectors/connector-jdbc-2.3.8.jar     connectors/connector-jdbc-2.3.8.jar.bak.$(date +%Y%m%d)

# ---- 替换新 JAR（从解压的增量包复制）----
tar xzf seatunnel-jars-only.tar.gz -C /tmp/
cp /tmp/jars/starter/seatunnel-starter.jar              starter/
cp /tmp/jars/connectors/connector-doris-2.3.8.jar        connectors/
cp /tmp/jars/connectors/connector-jdbc-2.3.8.jar         connectors/

# ---- 确认替换完成 ----
ls -lh starter/seatunnel-starter.jar                    # 应 ≈ 39M（新）
ls -lh connectors/connector-doris-2.3.8.jar              # 应 ≈ 12M（新）
```

### 1.4 修改配置文件

> 以下变更值均基于两个 Dump 文件中暴露出来的生产环境实际运行配置。每项变更标注了"生产当前值（Dump 确认）"→"变更后值"。

#### 🔴 必须 — CFG-1: `config/hazelcast*.yaml` 线程池参数

**生产当前值（Dump 确认）：`generic.thread.count = 50`，`operation.thread.count` 未配置（默认=32）**

```bash
cd $SEATUNNEL_HOME/config

# 编辑 hazelcast.yaml、hazelcast-master.yaml、hazelcast-worker.yaml 三个文件
# 找到 properties: 段，修改以下两行：
```

```yaml
properties:
  hazelcast.operation.generic.thread.count: 16     # 50 → 16
  hazelcast.operation.thread.count: 8              # 新增此行
```

> 三个 hazelcast-*.yaml 使用相同值即可（16 + 8），无需按 Master/Worker 差异化。

#### 🔴 必须 — CFG-2: `config/seatunnel.yaml` 历史 Job 过期

**生产当前值（Dump 确认）：`history-job-expire-minutes` 未配置（默认 1440 = 24h）**

在 `seatunnel:` → `engine:` 段下新增一行：

```yaml
seatunnel:
  engine:
    history-job-expire-minutes: 60      # 新增此行
```

#### 🟡 建议 — CFG-3: `config/hazelcast.yaml` 新增 IMap TTL

**生产当前值（Dump 确认）：`runningJobState`、`ownedSlotProfilesIMap`、`checkpoint-id-map` 三个表无 TTL**

在 `hazelcast.yaml` 的 `hazelcast:` 根节点末尾新增 `map:` 段：

```yaml
hazelcast:
  # ... 现有 properties: 等配置保持不变 ...
  map:
    engine_runningJobState:
      time-to-live-seconds: 3600
      max-idle-seconds: 1800
    engine_ownedSlotProfilesIMap:
      time-to-live-seconds: 3600
      max-idle-seconds: 1800
    engine_checkpoint-id-map:
      time-to-live-seconds: 3600
```

#### 🟡 建议 — CFG-4: `config/jvm_master_options` G1GC 调优

**生产当前值（Dump 确认）：`-Xmx8g -Xms8g -XX:+UseG1GC -XX:MaxMetaspaceSize=2g`（无额外 GC 参数）**

在现有参数末尾追加：

```bash
-Xmx8g -Xms8g -XX:+UseG1GC -XX:MaxMetaspaceSize=2g \
-XX:InitiatingHeapOccupancyPercent=40 \
-XX:+HeapDumpOnOutOfMemoryError \
-XX:HeapDumpPath=/tmp/seatunnel/dump/zeta-server
```

### 1.5 配置文件变更汇总

| 文件 | 节点 | 变更内容 | 紧迫度 |
|------|------|------|:--:|
| `config/hazelcast.yaml` | 所有节点 | `generic.thread.count` 50→**16**，新增 `operation.thread.count: 8` | 🔴 |
| `config/hazelcast-master.yaml` | Master | 同上 | 🔴 |
| `config/hazelcast-worker.yaml` | Worker | 同上 | 🔴 |
| `config/seatunnel.yaml` | 所有节点 | 新增 `history-job-expire-minutes: 60` | 🔴 |
| `config/hazelcast.yaml` | 所有节点 | 新增 `map:` 段（3 个 IMap 表 TTL=3600） | 🟡 |
| `config/jvm_master_options` | Master | 追加 `InitiatingHeapOccupancyPercent=40` | 🟡 |

### 1.6 启动服务

```bash
# 先启动 Master 节点
$SEATUNNEL_HOME/bin/seatunnel-cluster.sh -d

# 确认 Master 启动后，再启动 Worker 节点
$SEATUNNEL_HOME/bin/seatunnel-cluster.sh -d
```

## 二、验证步骤

### 2.1 配置生效确认（启动后立即执行）

```bash
# 获取进程 PID
MASTER_PID=$(jps | grep -i seatunnel | head -1 | awk '{print $1}')
WORKER_PID=$(jps | grep -i seatunnel | tail -1 | awk '{print $1}')
```

| 验证项 | 命令 | 预期结果 |
|------|------|:---:|
| GenericOperationThread 数量 | `jstack $PID \| grep "generic-operation" \| wc -l` | **16**（不再为 50） |
| PartitionOperationThread 数量 | `jstack $PID \| grep "partition-operation" \| wc -l` | **9** (8+1) |
| JVM GC 参数 | `jinfo $PID \| grep InitiatingHeapOccupancyPercent` | **40** |
| history-job-expire-minutes | 查看日志启动行 或 `grep expire $SEATUNNEL_HOME/config/seatunnel.yaml` | **60** |

### 2.2 内存状态观察（启动后 30 分钟内持续监测）

```bash
# 每 5 秒采样一次 GC 状态，观察 30 分钟
jstat -gcutil $MASTER_PID 5000 360
```

| 指标 | 命令/来源 | 修复前（Dump 值） | 目标 |
|------|------|:---:|:---:|
| 老年代占用率 | `jstat -gc $PID` OU 列 | > 99.99% | **< 80%** |
| Full GC 次数 | `jstat -gc $PID` FGC 列 | 频繁 | **0** |
| GC 暂停时间 | `jstat -gc $PID` FGCT 列 | — | 不持续增长 |

### 2.3 连接池/线程健康检查（运行 1 小时后执行）

| 验证项 | 命令 | 预期结果 |
|------|------|:---:|
| stream-load-check 线程数 | `jstack $PID \| grep "stream-load-check" \| wc -l` | **2**（不再为 12） |
| mysql 废弃连接线程 | `jstack $PID \| grep "mysql-cj-abandoned" \| wc -l` | **0**（不再为 2） |
| 连接池日志 | `grep "Doris HTTP Pool" $SEATUNNEL_HOME/logs/*.log` | 输出 pooled connection 统计 |

### 2.4 业务功能验证

```bash
# 提交一个最小规模的测试 Job，确认端到端数据同步正常
$SEATUNNEL_HOME/bin/seatunnel.sh \
  --config /path/to/test_job.conf \
  -m cluster
```

| 验证点 | 检查方式 | 合格标准 |
|------|------|------|
| Job 提交成功 | 终端输出 | `Job XXXX submitted successfully` |
| 任务执行完成 | `$SEATUNNEL_HOME/bin/seatunnel.sh -l` | Status = FINISHED |
| 数据同步正确 | 目标端 count 对比 | 源端 = 目标端 |
| 无异常日志 | `grep ERROR $SEATUNNEL_HOME/logs/*.log` | 无线程池/连接池相关 ERROR |

### 2.5 验证指标总览

| 指标 | 修复前（Dump 确认值） | 修复后目标 |
|------|:---:|:---:|
| GenericOperationThread | **50** | **16** |

## 三、回滚方案

### 3.1 回滚条件

出现以下任一情况时执行回滚：

- 启动后 30 分钟内发生 OOM
- 业务 Job 连续 3 次执行失败
- 出现与变更前不一致的数据同步异常
- 线程数、GC 指标持续恶化而非改善

### 3.2 回滚步骤

```bash
# ========== Step 1: 停服 ==========
$SEATUNNEL_HOME/bin/stop-seatunnel-cluster.sh
jps | grep -i seatunnel   # 确认进程退出

# ========== Step 2: 恢复 JAR 包 ==========
cd $SEATUNNEL_HOME

# 找到备份文件（按日期排序取最新）
ls starter/*.bak.* connectors/*.bak.*

# 恢复 JAR（替换为示例，以实际备份文件名为准）
cp starter/seatunnel-starter.jar.bak.20260615       starter/seatunnel-starter.jar
cp connectors/connector-doris-2.3.8.jar.bak.20260615 connectors/connector-doris-2.3.8.jar
cp connectors/connector-jdbc-2.3.8.jar.bak.20260615  connectors/connector-jdbc-2.3.8.jar

# ========== Step 3: 恢复配置文件 ==========
# 如果部署前已手工备份配置目录：
# cp -r $SEATUNNEL_HOME/config.bak.20260615/* $SEATUNNEL_HOME/config/

# 如果未备份，手工回退以下文件的修改：
#   config/hazelcast.yaml:          generic.thread.count 恢复为 50，删除 operation.thread.count
#   config/hazelcast-master.yaml:   同上
#   config/hazelcast-worker.yaml:   同上
#   config/seatunnel.yaml:          删除 history-job-expire-minutes 行
#   config/hazelcast.yaml:          删除 map: 段
#   config/jvm_master_options:      删除 InitiatingHeapOccupancyPercent 等追加参数

# ========== Step 4: 确认回退 ==========
grep "generic.thread.count" config/hazelcast*.yaml     # 应 = 50（恢复后）
grep "history-job-expire-minutes" config/seatunnel.yaml # 应无输出（恢复后）

# ========== Step 5: 启动服务 ==========
$SEATUNNEL_HOME/bin/seatunnel-cluster.sh -d  # Master
$SEATUNNEL_HOME/bin/seatunnel-cluster.sh -d  # Worker

# ========== Step 6: 验证回滚 ==========
jstack $(jps | grep seatunnel | head -1 | awk '{print $1}') | grep "generic-operation" | wc -l
# 应 ≈ 50
```

### 3.3 回滚后确认

| 确认项 | 方式 | 合格标准 |
|------|------|------|
| 线程数恢复 | `jstack` 统计 | GenericOperationThread ≈ 50 |
| 配置恢复 | `grep` 检查 | 与变更前一致 |
| 集群正常 | 提交测试 Job | Job 成功完成 |
| 数据正常 | 源/目标 count 对比 | 一致 |

### 3.4 回滚时间预估

| 步骤 | 操作 | 耗时 |
|:--|------|:--:|
| 停服 | stop-seatunnel-cluster.sh | < 1 分钟 |
| 恢复 JAR | cp 5 个文件 | < 1 分钟 |
| 恢复配置 | cp / 手工修改 | < 5 分钟 |
| 启动 | seatunnel-cluster.sh -d | < 2 分钟 |
| 验证 | 提交测试 Job | < 5 分钟 |
| **合计** | | **< 15 分钟** |
